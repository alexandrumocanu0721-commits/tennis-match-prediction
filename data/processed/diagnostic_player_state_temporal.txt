=== Task 1: State Engine Trace — ATP ===
scripts/atp/build_features.py replays every ATP match in chronological order, grouped by tourney_date.
For each date, it initializes players, refreshes rankings as of that match_date, snapshots state, builds feature rows from the snapshot, then applies post-match updates to Elo, surface Elo, form, H2H, fatigue, wins, and match counts.
The ranking helpers in scripts/atp/tennis_pipeline.py use the latest ranking_date <= match_date. Elo/form/H2H/fatigue updates are driven only by prior replayed matches; there is no cutoff check in feature generation.
Answer: ATP player state is live as of each match date, including 2025 and 2026 rows. It is not frozen at 2025-01-01.

=== Task 1: State Engine Trace — Challenger ===
scripts/challenger/build_challenger_features.py does the same chronological replay for Challenger matches, sorted by tourney_date and tourney_id, with per-day snapshots before feature creation and post-match state updates after rows are written.
Challenger Elo/form/H2H/fatigue state also keeps updating through the replay. Rankings are refreshed as of match_date when external ATP rankings are enabled; otherwise Challenger rank/points are neutral constants by configuration.
Answer: Challenger player state is also live as of each match date for dynamic features. Rank/points may be neutral-by-design if external rankings are disabled, but the state engine itself is not frozen at the training cutoff.
